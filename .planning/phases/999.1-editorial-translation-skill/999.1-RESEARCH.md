## Summary

The `editorial-translation` skill is a production-output skill (like `editorial-typesetting`) that translates finished nonfiction documents into a target language while preserving intent, register, formatting, and idiomatic voice. It does not run a diagnostic pass or write issues to `.agents/editorial-context.md` — it delivers a translated document.

The `baoyu-translate` skill in the repo root is an excellent reference implementation with a mature translation workflow, chunking engine (TypeScript/Bun scripts), glossary system, and content analysis step. The key adaptations for `editorial-translation` are: default language is Spanish rather than Chinese, Chinese-specific Europeanized-language checks are dropped, single-mode workflow replaces the three-mode structure, Codex is opt-in rather than primary, and integration with the editorial workflow context file is added.

The `codex` skill in `~/.claude/skills/codex/SKILL.md` uses `codex exec` with model/effort/sandbox flags. The current skill table lists `gpt-5.2-mini` as its latest mini model — the CONTEXT.md decision specifies `gpt-5.4-mini`, so the implementation must override the table with that specific model and note the override. The codex skill accepts prompts via a quoted string passed to `codex exec`; the `.tmp/` pattern for large input (5000-word chunks) avoids shell quoting limits and is appropriate.

**Primary recommendation:** Model `editorial-translation` structurally on `editorial-typesetting` (production output, reads context file but does not write issues to it, has an intake + generate + verify shape), adapt the full analysis+translate workflow from `baoyu-translate`'s normal mode, and integrate codex as an opt-in execution path via the pattern established in `~/.claude/skills/codex/SKILL.md`.

## Architecture Patterns

### Recommended Skill Structure

```
skills/editorial-translation/
├── SKILL.md                          # Main skill file (< 500 lines)
└── references/
    ├── ANALYSIS-WORKFLOW.md          # Detailed content analysis and translation steps
    ├── EXTEND-SCHEMA.md              # EXTEND.md preferences file schema
    └── STYLE-PRESETS.md              # Audience and style preset tables
```

The SKILL.md covers: frontmatter, context check, intake, EXTEND.md preferences, defaults table, workflow overview, chunking mechanics, codex integration, output structure, and workflow position. Detail tables and step-by-step analysis go in `references/`.

### Pattern 1: Production-Output Skill (modeled on editorial-typesetting)

**What:** Skill produces a delivered artifact (translated document), not an issue list. There is no diagnostic phase, no `## Translation Issues` section written to `.agents/editorial-context.md`.

**When to use:** Any editorial skill that is a production step rather than a review step.

**Shape:**
```markdown
## Two-Phase Process

**Phase 1 — Generate:**
1. Read `.agents/editorial-context.md` for audience, voice, style guide
2. Check/create EXTEND.md
3. Analyze source content → `{output-dir}/01-analysis.md`
4. Assemble translation prompt → `{output-dir}/02-prompt.md`
5. Translate (directly or via chunks/subagents) → `{output-dir}/translation.md`
6. Present summary to user

**Phase 2 — Review and Correction:**
User reviews output and asks for corrections if needed.
```

**Contrast with diagnostic-first skills:** `editorial-structural`, `editorial-development`, `editorial-line`, `editorial-copy`, and `editorial-proof` all write issue lists to `.agents/editorial-context.md` and offer two paths (manual edit vs. ask Claude to revise). `editorial-translation` and `editorial-typesetting` do not — they produce output and then accept correction requests.

### Pattern 2: Context File Integration (read-only)

**What:** Every skill reads `.agents/editorial-context.md` before asking questions. Translation reads it for audience profile and voice notes (set during prior editorial stages). It does NOT write to the context file.

```markdown
**Check for editorial context first:** If `.agents/editorial-context.md` exists, read it
before beginning. Use the audience profile, voice and tone notes, and style guide — only ask
for what's not already there.
```

**Key difference from diagnostic skills:** Diagnostic skills write issue lists to the context file under their prefix heading. Translation reads it but writes nothing back.

### Pattern 3: EXTEND.md Preferences

**What:** Project-level or user-level preferences file that stores per-project defaults (target language, audience, style, glossary, chunk settings). Adapted from baoyu-translate.

**Lookup priority (macOS/Linux):**
```bash
# 1. Project-level
test -f .editorial-skills/editorial-translation/EXTEND.md && echo "project"
# 2. User-level XDG
test -f "${XDG_CONFIG_HOME:-$HOME/.config}/editorial-skills/editorial-translation/EXTEND.md" && echo "xdg"
# 3. User home
test -f "$HOME/.editorial-skills/editorial-translation/EXTEND.md" && echo "user"
```

**On first use:** If EXTEND.md not found, prompt user (language, audience, style, save location) and create it. This is the same blocking first-time-setup pattern from baoyu-translate.

**EXTEND.md schema (YAML):**
```yaml
target_language: es           # Default: es (Spanish)
source_language: auto         # Default: auto-detect
audience: general             # general | technical | academic | business | custom
style: elegant                # storytelling | formal | technical | literal | academic | business | humorous | conversational | elegant | custom
chunk_threshold: 4000         # Word count to trigger chunked translation
chunk_max_words: 5000         # Max words per chunk
glossary:
  - from: "source term"
    to: "target translation"
    note: "optional usage note"
glossary_files:
  - ./my-glossary.md
```

**Note on style default:** `elegant` may be more appropriate than `storytelling` as default for nonfiction books aimed at Spanish-language readers. This is Claude's discretion per CONTEXT.md.

### Pattern 4: Chunking with baoyu-translate Scripts

**What:** For documents exceeding chunk threshold, split at markdown block boundaries using the existing `chunk.ts` / `main.ts` scripts from `baoyu-translate/scripts/`. Translate chunks in parallel via subagents when Agent tool is available.

**Script invocation:**
```bash
${BUN_X} {baseDir}/scripts/main.ts <file> [--max-words <chunk_max_words>] [--output-dir <output-dir>]
```

`{baseDir}` = absolute path to `skills/editorial-translation/` directory. `${BUN_X}` = `bun` if installed, else `npx -y bun`.

**How the chunker works (HIGH confidence — read from source):**
1. Strips YAML frontmatter, saves to `chunks/frontmatter.md`
2. Parses markdown into blocks: headings, thematic breaks, HTML, code fences, and flow (paragraphs, lists, tables)
3. Splits into sections at heading boundaries
4. Packs sections into chunks up to `maxWords`
5. If a single block exceeds limit: line-splits, then word-splits as fallback
6. Outputs `chunks/chunk-01.md`, `chunks/chunk-02.md`, etc.

**Key limitation:** `countWords()` in `chunk.ts` counts CJK characters and Latin alphanumerics. For Spanish (Latin script), word count is accurate. No adjustment needed.

**For codex path:** When codex engine is selected, chunks go to `.tmp/` instead of the output directory's `chunks/` subdirectory. This avoids passing 5000-word content via shell string quoting.

### Anti-Patterns to Avoid

- **Writing issues to `.agents/editorial-context.md`:** This skill does not write issue lists. It reads the context file for audience and voice data only.
- **Running a diagnostic pass before translating:** Per D-05, there is no Phase 1 diagnostic. The skill goes directly to analysis-then-translate.
- **Using `--mode` flag (three modes):** There is only one mode per D-07. If user asks for "quick" or "refined" mode, note that this skill has one quality-focused workflow.
- **Defaulting to Chinese:** Default target language is Spanish (`es`) per D-10. All examples in SKILL.md and references should use Spanish.

## Common Pitfalls

### Pitfall 1: Forgetting the `.agents/editorial-context.md` Read-Only Rule

**What goes wrong:** Skill writes issue findings or translation notes to `.agents/editorial-context.md`, polluting the editorial issue log with non-issue content.

**Why it happens:** Six of seven existing editorial skills write to the context file. `editorial-translation` is one of two (with `editorial-typesetting`) that only reads it.

**How to avoid:** The skill must explicitly state: "Read `.agents/editorial-context.md` if it exists — do not write to it." Make this visible in the context-check pattern.

**Warning signs:** If SKILL.md has any instruction to write a `## Translation Issues` heading or any `T#` prefixed entries to the context file, that is wrong.

### Pitfall 2: Chunk Boundary Disrupts Sentence or Paragraph

**What goes wrong:** A sentence or paragraph is split across two chunks, producing a broken sentence at the end of one chunk and a fragment at the start of the next.

**Why it happens:** The chunker splits at markdown block boundaries (paragraphs, headings), not mid-paragraph. However, if a single paragraph exceeds the chunk max, line-splitting is used as fallback, which can break at arbitrary line endings.

**How to avoid:** Chunk max words (5000) is generous enough that most prose paragraphs (typically 100–300 words) will not trigger line-level splitting. The chunker's fallback is line-split then word-split — line-split preserves sentence boundaries in most well-formatted markdown. Flag this risk in references but do not over-engineer.

**Warning signs:** After merging chunks, review translation for awkward sentence-starts ("...it follows that") or abrupt endings that lack a closing period.

### Pitfall 3: Codex Model Version Staleness

**What goes wrong:** The codex SKILL.md model table is updated; the editorial-translation skill hardcodes `gpt-5.4-mini` which may become outdated.

**Why it happens:** CONTEXT.md D-04 specifies a model by name. Model names change.

**How to avoid:** Note in SKILL.md that `gpt-5.4-mini` is the model as of skill creation, and direct users to check the codex skill's model table if they want to use a newer model. Do not pin so tightly that the skill becomes wrong silently.

### Pitfall 4: Forgetting to Strip Chinese-Specific Content from Adapted References

**What goes wrong:** Analysis workflow reference includes the Europeanized-language critique section from baoyu-translate with Chinese-specific checks (被/由/受到 passive voice, 是...的 cleft sentences), which are irrelevant for Spanish or most European target languages.

**Why it happens:** Copy-paste adaptation without removing Chinese-targeted content.

**How to avoid:** The `ANALYSIS-WORKFLOW.md` reference file should replace Section 4.2 ("Europeanized Language Diagnosis for CJK targets") with a general non-Europeanization check: flag unnatural calques, stilted word order, and literal translations of idioms — without CJK-specific examples.

### Pitfall 5: First-Time Setup Blocking Not Enforced

**What goes wrong:** Skill silently uses Spanish defaults when no EXTEND.md is found, without asking the user to confirm target language. User's document gets translated to Spanish when they wanted French.

**Why it happens:** Implementing EXTEND.md lookup without the blocking first-time setup from baoyu-translate.

**How to avoid:** When EXTEND.md is not found, run a blocking setup: ask target language (default Spanish), source language (default auto), audience, style, and save location in one AskUserQuestion call. Create EXTEND.md before translating.

### Pitfall 6: `.tmp/` Files Not Cleaned Up

**What goes wrong:** `.tmp/` directory accumulates prompt files from each codex run, polluting the working directory.

**Why it happens:** Codex path writes temp files but has no cleanup step.

**How to avoid:** After codex run completes (success or failure), remove `.tmp/` files created for that run. Consider naming temp files with a timestamp or session ID to avoid collisions.

### Workflow Step Sequence (adapted from baoyu-translate normal mode)

```markdown
## Workflow

### Step 1: Load Preferences
1. Check EXTEND.md (project → XDG → home)
2. If not found: run first-time setup (BLOCKING)
3. Apply settings; merge with CLI flags (CLI overrides EXTEND.md)

### Step 2: Read Context
Read `.agents/editorial-context.md` if it exists.
Load: audience profile, voice and tone notes, style guide preferences.
Do not ask for what is already there.

### Step 3: Materialize Source and Create Output Directory
- File: use as-is
- Inline text: save to `translate/{slug}.md`
- URL: fetch content, save to `translate/{slug}.md`
Output directory: `{source-dir}/{source-basename}-{target-lang}/`
If directory exists: rename to `{name}.backup-YYYYMMDD-HHMMSS/`

### Step 4: Assess Content Length
Estimate word count.
- < chunk threshold (default 4000): translate as single unit
- >= chunk threshold: chunked translation (see Step 4.1)

### Step 4.1: Long Content Preparation (>= threshold only)
1. Extract terminology: scan for proper nouns, technical terms, recurring phrases
2. Build session glossary: merge extracted terms + EXTEND.md glossary + --glossary file
3. Split into chunks:
   ${BUN_X} {baseDir}/scripts/main.ts <file> [--max-words <chunk_max_words>] [--output-dir <output-dir>]
4. Save chunk scripts output to output-dir/chunks/

### Step 5: Analyze
Analyze full source (or single unit if not chunked):
- Quick summary (3-5 sentences)
- Core argument, key concepts, structure
- Author background and writing context
- Terminology extraction → working terminology table
- Tone and register assessment
- Reader comprehension challenges (calibrated to audience)
- Figurative language and metaphor mapping
Save to: {output-dir}/01-analysis.md

### Step 6: Assemble Translation Prompt
Read 01-analysis.md. Inline: style preset, content background, merged glossary,
comprehension challenges. Save to {output-dir}/02-prompt.md.

### Step 7: Translate
If Agent tool available and content is chunked:
  - Spawn one subagent per chunk in parallel
  - Each reads 02-prompt.md + translates its chunk → saves chunk-NN-draft.md
  - Merge all chunks in order; prepend frontmatter.md if present
  - Save merged result to translation.md
If not chunked or Agent unavailable:
  - Translate source following 02-prompt.md → save to translation.md

### Step 8: Output Summary
Display: Source, Languages (from → to), Output dir, Final file path, Glossary terms applied.
```

### Figurative Language Mapping (non-CJK version)

Adapted for Spanish and general target languages (replaces baoyu-translate's CJK-specific Step 4.2):

```markdown
### Non-Europeanization Check (for any target language)

Flag translations that carry the structural fingerprint of English rather than natural target-language expression:

- **Unnatural calques**: Phrases translated word-for-word that produce unnatural constructions in the target language
- **Literal idiom translation**: English idioms rendered literally rather than substituted with a target-language equivalent
- **Awkward subordination**: English-style stacked subordinate clauses that should be broken into shorter sentences in the target language
- **Over-formalization**: Translating informal English prose into register-shifted formal target language (common in English→Spanish where there are multiple register options)
- **Register inconsistency**: Mixing formal and informal register (tú vs. usted in Spanish) within a single document
```

## Open Questions

1. **Scripts location: copy vs. reference**
   - What we know: `baoyu-translate/scripts/main.ts` and `chunk.ts` exist and work. CONTEXT.md says they "may be copied into `editorial-translation/scripts/` or referenced if baoyu-translate stays in the repo."
   - What's unclear: Will `baoyu-translate` remain in the repo long-term? Copying avoids a cross-skill dependency; referencing avoids duplication.
